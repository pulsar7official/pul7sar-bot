# PUL7SAR Phase 18 — Change Set 171

## Lease-Bound Resource Evidence Seal

This change closes an evidence gap immediately before the first genuine Golden Candidate execution.

Phase 18 already requalified live GPU state and live system RAM after a concrete job lease and before FLUX could enter `RUNNING`. That safety guard prevented execution under degraded resources, but the exact last-moment resource proof was ephemeral. If Candidate 1 eventually succeeds, we also need durable evidence of the physical resource state that allowed FLUX to begin.

## Added

### `engine/intelligence/execution_resource_evidence.py`

Adds `LeaseBoundExecutionResourceEvidenceStore` and `LeaseBoundExecutionResourceReceipt`.

The store accepts only a real `LEASED` `GenerationJob` owned by the worker writing the evidence. It validates the combined GPU + host-memory requalification payload and refuses to persist evidence unless:

- GPU qualification is eligible;
- native BF16 is still proven;
- execution remains `$0-local`;
- GPU requalification did not mutate the queue or grant generation/publication authority;
- live host-memory qualification is ready;
- host-memory requalification did not mutate the queue or grant generation/publication authority.

The receipt is attempt-bound and written atomically as:

`<job-id>-attempt-<attempt>-execution-resource.json`

It records request/job identity, locked payload SHA-256, provider/model identity, UTC observation time, exact GPU evidence, exact host-memory evidence, and explicit non-authority fields.

### `tests/test_phase18_execution_resource_evidence.py`

Regression coverage for:

- attempt-bound receipt creation;
- SHA/byte metadata;
- rejection of non-leased jobs;
- rejection of a worker that does not own the lease;
- rejection of GPU or host-memory authority drift;
- rejection of unready live resource evidence.

## Modified

### `tools/phase18_gpu_worker.py`

The lease-bound `pre_execute_guard` now performs the same combined live GPU + host-memory requalification and immediately seals the resulting evidence before the job can transition to `RUNNING` or invoke FLUX.

A new CLI option is available:

`--resource-evidence-root` (default: `output/phase18_worker_results`)

Worker readiness, heartbeat, performance metadata, and cycle output now declare that lease-bound resource evidence is enabled and identify its storage root.

### `tests/test_phase18_worker_host_memory_guard.py`

Updated source-order assertions for the stronger behavior:

- the post-lease guard must call `_record_lease_bound_execution_evidence(...)`;
- that helper must requalify both GPU and host RAM;
- the resource evidence store must exist before `GenerationWorkerService` construction;
- cycle-level requalification must still occur before queue recovery and lease execution.

## Why this reduces the remaining Golden gap

The first successful Candidate 1 must not merely prove that a worker once passed a resource check. It should preserve evidence from the exact post-lease/pre-FLUX boundary. Change Set 171 makes that evidence durable and attempt-specific, so later provenance work can bind the genuine PNG to the resource state under which execution actually began.

No PNG is generated by this change set. GPU execution remains blocked until a compatible physical CUDA/BF16 host is available.
