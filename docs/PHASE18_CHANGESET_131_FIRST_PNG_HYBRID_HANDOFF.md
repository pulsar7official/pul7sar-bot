# Phase 18 Change Set 131 — First-PNG Hybrid Handoff

## Purpose

Close the remaining orchestration gap between the genuine Candidate 1 GPU smoke path and the existing Golden Hybrid v5 semantic/composition path.

Before this change, `phase18_first_png.py` could produce and provenance-replay a genuine FLUX.2 Klein Candidate 1, while the Hybrid v5 semantic/composition flow consumed `output/phase18_colab/latest.json`. The two paths did not share a canonical bridge, so a valid GPU-smoke PNG could require a separate generation-oriented runner before entering Base Scene semantic/layer QA.

## Added

- `engine/intelligence/first_png_hybrid_handoff.py`
  - requires `phase18/story-intelligence`;
  - requires Golden manifest v5 and the current deterministic-football/brand-ownership contract;
  - requires `FIRST_GOLDEN_PNG_PROVENANCE_POSTFLIGHT_VERIFIED` for Candidate 1;
  - requires `$0-local` and `bfloat16`;
  - recomputes SHA-256 for the PNG, executor result and proof metadata;
  - rejects repository path escape, stale/tampered evidence, manifest drift or publication-authority drift;
  - emits `FIRST_GOLDEN_PNG_HYBRID_HANDOFF_READY` while keeping semantic, Golden-quality and publication gates closed.

- `tools/phase18_build_first_png_hybrid_handoff.py`
  - converts the verified first-PNG postflight into the canonical Hybrid v5 base summary;
  - defaults to `output/phase18_colab/latest.json` so the existing Hybrid v5 semantic/composition consumer can continue from the same bytes without rerunning FLUX.

- `tests/test_phase18_first_png_hybrid_handoff.py`
  - covers the valid bridge, publication/semantic authority drift, PNG tampering, executor tampering, stale manifest version and branch escape.

- `tests/test_phase18_gpu_smoke_hybrid_handoff.py`
  - locks workflow ordering: generation → provenance postflight → Hybrid handoff → evidence sealing;
  - proves the handoff remains BF16/$0-local and cannot self-authorize semantic, Golden or publication status.

## Modified

- `.github/workflows/phase18-gpu-smoke.yml`
  - builds the Hybrid v5 handoff immediately after first-PNG provenance replay;
  - validates Candidate 1, Golden v5, BF16, `$0-local`, deterministic surface ownership and closed downstream gates;
  - seals the handoff into the tamper-evident GPU evidence manifest;
  - uploads `output/phase18_colab/**` with the GPU artifact so the exact proven base is ready for the next semantic/composition step.

## Deleted

Nothing.

## Gates preserved

No changes were made to Fact Lock, identity verification, sentiment/neutrality, `$0-local`, FLUX.2 Klein 4B, native BF16, seeds/canvases, generated-text/brand/score/crest/geometry exclusions, Qwen semantic inspection, deterministic football geometry, SemanticPublicationGate, Golden 8.5/9.0 thresholds, exact brand integrity or typography integrity.

The new handoff explicitly reports:

- `semantic_layer_gate_approved=false`
- `hybrid_semantic_review_approved=false`
- `golden_quality_approved=false`
- `publication_ready=false`

## Why this materially reduces the remaining gap

A genuine Candidate 1 generated by the self-hosted GPU path no longer needs a second generation-oriented path to become consumable by Hybrid v5 QA. The exact same provenance-locked PNG can move directly into the existing Base Scene semantic/layer ownership gate and deterministic football composition path.

The remaining external blocker is still a compatible NVIDIA CUDA + BF16 host on which to run Candidate 1. This change does not fabricate a PNG or benchmark when that hardware is unavailable.
