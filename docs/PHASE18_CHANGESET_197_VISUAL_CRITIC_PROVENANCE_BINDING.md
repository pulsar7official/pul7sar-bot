# Phase 18 Change Set 197 — Visual Critic Provenance Binding

## Scope

Branch only: `phase18/story-intelligence`.

This change set does **not** modify `main`, `main.py`, production publishing, Fact Lock, entity/identity verification, sentiment/neutrality, zero-cost execution, SemanticPublicationGate, Golden visual thresholds, or exact brand/typography gates.

## Why this change was needed

The current Visual Brain architecture now does two useful things before and after rendering:

1. it competes several genuinely different editorial concepts instead of merely trying several seeds of the same composition; and
2. it applies a fail-closed Visual Critic that can reject geometry defects, pseudo-text, identity/factual violations, generation defects, weak editorial specificity, weak visual impact, poor composition, poor photographic coherence, poor concept fidelity, and stock-like imagery.

A remaining trust gap was that a critic JSON could name a `concept_id` and provide scores without proving that those scores referred to the **exact PNG bytes** created by the selected Visual Brain candidate. In a multi-concept benchmark this is unacceptable: evidence for concept A must never be reusable for concept B, an older seed, or a modified PNG.

## Added

### `engine/intelligence/visual_brain_critic_provenance.py`

Adds a fail-closed provenance gate that binds critic evidence to:

- the canonical `pul7sar-visual-brain-batch-v1` manifest;
- benchmark `visual-brain-preview-season-return-v1`;
- the exact candidate number;
- `concept_id`;
- `request_id`;
- seed;
- handoff `payload_sha256`;
- approved provider/model identity;
- `$0-local` generation;
- a genuine `REAL_VISUAL_PROOF_GENERATED` result;
- the exact generated PNG path and SHA-256;
- SHA-256 of the batch manifest, generation-result JSON, and critic-evidence JSON.

It then delegates the visual decision to the existing `VisualCriticGate`. A rejected critic decision remains rejected. An accepted critic decision remains **necessary but not sufficient** for downstream Golden/publication approval.

The resulting receipt always keeps:

- `human_visual_review_required = true`;
- `golden_quality_approved = false`;
- `publication_ready = false`.

Repository path traversal is rejected.

### `tools/phase18_verify_visual_brain_critic_provenance.py`

CPU-only verifier CLI for the binding above. It writes an optional machine-readable receipt and returns non-zero when the critic rejects the candidate. It does not run FLUX, does not mutate a queue, does not call a paid provider, and cannot open publication.

### `tests/test_phase18_visual_brain_critic_provenance.py`

Regression coverage for:

- successful premium/safe evidence bound to exact generated bytes;
- PNG tampering after evidence creation;
- candidate/seed identity drift;
- hard visual failure remaining rejected and non-publishable;
- repository path escape rejection.

## Modified

No pre-existing runtime file was modified in this change set. The implementation is additive on top of the current Visual Brain concept-competition and critic contracts.

## Deleted

Nothing.

## Safety / quality invariants preserved

Unchanged and fail-closed:

- factual integrity / Fact Lock;
- entity and identity verification;
- sentiment and result neutrality;
- `$0-local` execution policy;
- pinned FLUX/Qwen model policy;
- no generated PUL7SAR branding or exact editorial facts;
- no unauthorized sport geometry;
- semantic/layer ownership gates;
- Golden visual quality floor (`8.5`, elite target `9.0+`);
- exact brand and typography integrity;
- SemanticPublicationGate and final publication readiness.

## Impact toward the first accepted genuine Golden Visual

The current project already has genuine visual evidence, including rejected candidates. The target is now the first **accepted** genuine Golden Visual. This change materially reduces the gap because a future candidate cannot receive a Visual Brain acceptance using critic evidence belonging to a different concept, seed, request, or modified image.

The next GPU-produced Visual Brain candidate can therefore move through:

`concept-diverse handoff → genuine PNG → byte-bound critic evidence → explicit human review → Golden 8.5/9.0+ review → exact brand/typography → SemanticPublicationGate`

without weakening any existing gate.
